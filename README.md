# Sulukera Academic Calendar

نظام تقويم وجدولة أكاديمية لسلوكيرا، مبني كموقع ثابت على GitHub Pages مع Firebase Authentication وFirestore.

## الصفحات

- `index.html`: التقويم العام للطلاب والخطط المنشورة.
- `planner.html`: المخطط الذكي للإدارة (قوالب، تعارضات، مسودة/نشر).
- `admin.html`: إدارة تقاويم البرامج القديمة والفصول.
- `schedule.html`: جداول المحاضرات.
- `savethedate.html`: بطاقات مواعيد بدء البرامج.

## القوالب الذكية

- ABA: الدفعة ستة فصول؛ كل فصل أربعة أسابيع دراسة وأسبوع اختبارات، يتبعه أسبوع إجازة فاصل.
- OBM Practitioner: ثلاث وحدات، أسبوعان لكل وحدة.
- OBM Advanced: الوحدات الرابعة والخامسة والسادسة، أسبوعان لكل وحدة.

## تشغيل محلي

استخدم أي خادم ملفات ثابتة؛ فتح الملفات مباشرة عبر `file://` لا يشغّل ES modules بشكل موثوق.

```powershell
python -m http.server 8080
```

ثم افتح `http://localhost:8080/`.

## Firebase

انشر قواعد الأمان قبل استخدام مجموعة `academic_plans`:

```powershell
firebase deploy --only firestore:rules
```

المفتاح الموجود في إعداد Firebase هو معرّف تطبيق ويب وليس سرًا. الحماية تعتمد على Authentication وFirestore Rules.

## مصادر الإجازات

الإجازات الثابتة (يوم التأسيس واليوم الوطني) والتواريخ المؤكدة تحفظ في `js/scheduler.js`. تواريخ الأعياد المستقبلية تحمل حالة `tentative` إلى أن يصدر الإعلان الرسمي.

## إدارة برامج 2027

افتحي `planner.html` واختاري أحد القوالب لتوليد الأسابيع، أو «برنامج بتواريخ محددة» لتسجيل موعد واحد أو فترة ببداية ونهاية. اختاري «معاينة المواعيد» ثم احفظي مسودة أو انشريها للطلاب. تقويم الطلاب يفتح على 2027 ويتيح استعراض السنوات الأخرى. الخطط الممتدة عبر سنتين تظهر في كل سنة ضمن أشهرها.

### تفعيل صلاحيات الإدارة

قبل نشر الواجهة والقواعد الجديدة، أضيفي مطالبة Firebase المخصصة `admin: true` لحسابات الإدارة المصرح لها باستخدام Firebase Admin SDK في بيئة موثوقة. احتفظي بالمطالبات الحالية عند التحديث. مثال داخل مشروع مُهيأ مسبقًا باستخدام Admin SDK:

```js
const auth = getAuth();
const user = await auth.getUser(uid);
await auth.setCustomUserClaims(uid, { ...user.customClaims, admin: true });
```

بعدها سجّلي الخروج والدخول لتحديث رمز الحساب. انشري القواعد مع الواجهة الجديدة. مجموعة `planner_state` تُنشأ عند أول حفظ وتنسّق تحديثات الخطط المتزامنة.

الفصول الموجودة تحتفظ بمفاتيح جداولها القديمة عند أول حفظ للفصول من لوحة الإدارة. الفصول الجديدة تحصل على معرّفات ثابتة. إذا كان جدول قد ارتبط بفصل خاطئ قبل التحديث، فراجعيه يدويًا من صفحة الجداول.
